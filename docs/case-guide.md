# Как делать кейсы и страницы сайта

Правила собраны по двум готовым кейсам: «Цифровая платформа для школ» (`site/src/pages/cases/my-school.astro`) и medx.pro (`site/src/pages/cases/medx.astro`). Новый кейс должен с первого раза выглядеть как они. Если правило здесь расходится с кодом, верен код готовых кейсов. Тогда документ нужно поправить.

## 1. Для кого и как пишем

- Кейс читают UI/UX-специалисты. Показываем, а не объясняем. Не подписываем очевидный интерфейс и не приводим банальных цифр, которые есть в любом таком проекте. Детали Дмитрий расскажет на собеседовании.
- Масштаб описываем словами («запускали по всей стране»), без «80+ регионов».
- Только реальные факты. Исследования, метрики, цитаты и истории «до/после» не выдумываем. Если чего-то не хватает, спрашиваем Дмитрия.
- Тон официальный и ровный. Обычно один абзац на блок, у секции один лид.
- Доступность не подаём как достоинство, это база.
- Вёрстка называется «отзывчивая», никогда не «адаптивная». Конкретные брейкпоинты в тексте не перечисляем.
- Карты России всегда с Крымом.
- Под NDA: скриншоты превращаем в абстрактные формы, чтобы продукт не узнавался. Реальные бренды заменяем.
- В тексте без висячих коротких слов. Это делает типограф сборки (`site/integrations/typograph.mjs`): неразрывные пробелы после предлогов и союзов, слова через дефис до 20 символов не переносятся. Правило «без висячей последней строки» Дмитрий отменил, его не возвращаем.
- Рядом стоящие тексты выравниваем одинаково. Нельзя мешать подписи в одну и в две строки или по центру и по левому краю.

## 2. Структура кейса

**Шапка** одинаковая во всех кейсах, её не переделываем:
- текст слева, визуал справа;
- h1 — название кейса;
- лид — то же описание, что в карточке проекта на главной;
- ниже строка мета: **Роль, Период, Команда, Аудитория**. Набор полей везде один.

От кейса к кейсу меняется только визуал справа. Он должен быть живым: анимированный фрагмент настоящего интерфейса. Он не повторяет обложку и отличается от визуалов других кейсов.

**Порядок секций.** За основу берём уже сделанные кейсы. Убираем то, чего в проекте не было.

| Школы | medx.pro |
|---|---|
| Контекст | Контекст |
| Задача и проблема | Задача и проблема |
| Что я делал | Что я делал |
| Для кого: две роли | Для кого |
| Персоны | Схема вместо абзаца |
| Исследование | Дизайн-система |
| Принципы | Лонгрид в действии |
| От вайрфрейма к интерфейсу | Концепт «Моё обучение» |
| Дизайн-система | Результаты |
| Анатомия урока | |
| Иллюстрации | |
| Лонгрид в действии | |
| Результаты | |

- Без декоративных номеров секций («03»).
- Секция всегда собрана в одну колонку: сверху заголовок, под ним лид, под лидом блок на всю ширину. Раскладку «заголовок слева, контент справа» не используем.
- Под кейсом кнопка «Посмотреть все работы». Отступ под ней такой же, как сверху у секции.

## 3. Визуалы

- Иллюстрируем только настоящими макетами Дмитрия: фрагменты, пересобранные в коде из его канвасов. Выдуманный интерфейс и описательные картинки не годятся.
- Встроенные фрагменты интерфейса живые: курсор кликает, блоки появляются и переключаются. Статичных вставок нет. Новый кейс сначала делаем статично, анимацию добавляем после того, как Дмитрий одобрит статику.
- Графика простая и читается с одного взгляда. Сложные CJM и кривые эмоций не нужны. Исследование подаём как «боль → решение».
- Вокруг графики нет декоративных белых рамок. Карта или схема стоит свободно рядом с текстом.
- Сложные макеты на узких экранах не перестраиваются, а уменьшаются целиком. Для этого есть обёртка `.sc-scale` с `--base: <ширина макета>px`. Перестраиваем только то, что без перестройки нельзя прочитать. Пример — «Хронология вспышек» в medx.pro на ширине до 899px.
- Слайдеры показывают счётчик «1 / N» с реальным числом слайдов. Точек-пагинации нет.
- Иконки только Iconsax (см. `AGENTS.md`):
  - **Bold** — в плашках категорий и в цветных плитках карточек («Что я делал», «Для кого»);
  - **Linear** — в кнопках и контактах.
- Иконки внутри макетов одной толщины на всех ширинах. Не используем `vector-effect: non-scaling-stroke` в блоках, которые масштабируются через `.sc-scale`: на телефоне такие линии кажутся жирнее.
- 3D (WebGL) на сайте допустим позже.
- Статичные экраны-картинки открываются крупно по клику. Селекторы таких картинок перечислены в `site/src/scripts/zoom.ts`. Класс картинок нового кейса добавляем туда. Живые макеты и картинки внутри слайдеров и сравнений не увеличиваем.

## 4. Шрифты и вес страницы

- Шрифт сайта — **Onest**: оболочка страниц, главная, контакты, тексты кейсов. Его нельзя убирать. Если страница попадает в чужую обёртку (например, в артефакт), Onest задаётся на `body` явно.
- Шрифты макетов (Geologica у школ, Manrope + PT Serif у medx.pro) страница не грузит. Весь текст макетов превращается в SVG-кривые при сборке (`site/integrations/curves.mjs`).
- Если текст в макете поменялся, сборка падает. Тогда перегенерируем кривые: `tools/case-curves/run.sh <страница>`, где страница — это `my-school`, `medx`, `home` или `work`. Шрифты новой страницы прописываются в `tools/case-curves/fonts.json`.
- В CSS правила вида `.x svg { … }` пишем как `svg:not(.cv)`, иначе они задевают слова-кривые.
- Обложки на главной и в «Моих работах» — живой HTML, тоже в кривых. Видео не используем. Начиная с третьего кейса обложки ниже первого экрана подгружаем лениво.

## 5. Сетка и ритм

| Что | Значение |
|---|---|
| Ширина контента | 1320px (`--page-width`) |
| Боковые поля страницы | 64px, до 1199px — 32px, до 599px — 20px (`--page-gutter`) |
| Отступ между секциями сверху и снизу | 96px на 1440 → 72px на 375, плавно (`--sec-pad`) |
| Заголовок → лид → блок | 32px → 24px, плавно (`--flow`) |
| Между карточками в сетке | 16px |
| Минимальная ширина экрана | 320px. Вёрстка обязана работать на любой ширине от 320px |

Ритм страницы (`--sec-pad`, `--flow`) уменьшается к мобилке плавно, через `clamp()`, в одной пропорции 3 : 4. Это единственное, что сжимается.

### Правило близости

- Что связано по смыслу, стоит ближе, чем то, что не связано.
  - Заголовок карточки и её текст — одна группа, стоят плотно.
  - Иконка — отдельный элемент. От иконки до заголовка визуально столько же, сколько от края карточки до иконки.
- Отступы сравниваем **визуально**, а не по CSS. Меряем до самих букв, а не до строки: у строки есть воздух над и под буквами. Поэтому CSS-отступ часто нужно делать меньше или больше номинала. Примеры:
  - иконка → заголовок в карточках «Что я делал» и «Для кого»: в CSS добавлено 11–12px к отступу;
  - отступ между двумя абзацами равен отступу от абзаца до фрейма под ним (`calc(var(--flow) - .45em)`).
- Внутри компонентов (карточки, персоны, цифры, цитаты, плашки) отступы на мобилке **такие же, как на десктопе**. Новые мобильные отступы не придумываем. Когда колонки встают друг под друга, промежуток между ними — обычный промежуток блока.
- Аватар или иконку рядом с многострочным заголовком выравниваем по верху, а не по центру.

## 6. Скругления, цвета, тени

| Элемент | Скругление |
|---|---|
| Карточки контента кейса (цифры, «Что я делал», «Для кого», очередь вопросов) | 12px |
| Обложки проектов на главной | 12px, до 599px — 10px (`--card-radius`) |
| Плитка иконки в карточке, 56×56 | 14px |
| Плашки, бейджи, мелкие кнопки в макетах | по токенам макета проекта, не по сайту |
| Аватары персон | 72px, квадрат со скруглением 20px, не круг |
| Плашки категорий, навигация, кнопки сайта | полностью круглые (100px) |

- Фон страницы `#fafafa`. Карточки белые, без обводки. Обводки вокруг фона и цветовых образцов Дмитрий просил убирать.
- Основной текст `#23242b`, вторичный `#777984` (`--text-secondary`).
- У каждого кейса своя палитра, заданная на `.sc` через `--p` (акцент), `--pl` (светлый акцент), `--t`, `--cap`, `--bg`, `--line`. Школы — синий `#006ee5`, medx.pro — зелёный `#3b876a`. Палитра берётся из макетов проекта. Плитки иконок `--pl`, сами иконки `--p`.
- Тени считаем устаревшим приёмом (Дмитрий, 2026-11-06). Экраны-картинки и рамки в кейсе отделяем обводкой 1px цвета `--line` палитры кейса. Если тень где-то осталась, она только мягкая (`--shadow-card`, `--shadow-head`).
- Картинку в шапке кейса не увеличиваем по клику.

## 8. Карточка проекта на главной и в «Моих работах»

- Обложка — живая анимация из настоящего дизайна проекта, а не из дизайн-системы. Пропорции рамки у всех кейсов одинаковые, сама композиция у каждого своя.
- Под обложкой заголовок, справа от него две плашки категорий: «UX/UI» и отрасль («Edtech», «Medtech»). Иконки плашек — Iconsax Bold, связь задаётся в `site/src/components/CategoryIcon.astro`. Ниже описание, то же, что лид в шапке кейса.
- На телефоне (до 599px) порядок такой: заголовок, описание, плашки.
- Новый кейс добавляется в `site/src/data/projects.ts`.

## 9. Перед публикацией

1. `pnpm build` в `site/`. Если упало из-за кривых, запускаем `tools/case-curves/run.sh`.
2. Проверяем в браузере ширины 1440, 900, 375 и 320.
3. Артефакт сайта собираем через `python3 tools/artifact-relativize.py site/dist <папка>` и публикуем изменённые HTML и новые ассеты. Старые CSS-файлы не удаляем: на них ссылаются закэшированные страницы.
4. В `main` не вливаем, пока Дмитрий не скажет. Рабочие ветки — это тестовая версия.
